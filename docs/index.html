长期记忆与陪伴新特性

从“模型自己写 MEMORY.md”升级为结构化、可审核、可迁移的长期记忆系统。

Memory

SQLite 长期记忆

workspace/memory/memory.db 是唯一运行时事实源；旧 MEMORY.md 不再读取。支持分层条目、关系状态、人格与来源追踪。

Dedupe

去重与冲突替代

精确哈希 + 中文相似度 + SimHash 近似合并；同一事实变化时保留历史版本。

Review

人工审核队列

不确定的记忆停留在 pending_review，审核通过前不进入提示词。

Companion

关系与人格

称呼、关系阶段、亲密边界、纪念日与版本化人设，适合长期陪伴场景。

Dashboard

记忆控制台

Launcher 的 /memory 页面集中完成查看、跨层搜索、审核、关系/人格、设置与数据库修复。

Portable

workspace 自由迁移

不保存机器相关绝对路径；相对 workspace + WAL checkpoint，复制目录即可换机。

无需自建前端，直接接入现有聊天渠道

PicoClaw 是自托管网关。你可以在 QQ、微信/企业微信、飞书、钉钉里直接和它对话，也可以使用内置 Launcher；不需要再开发一套 Web 聊天前端。

把 AI 放进你已经在用的聊天软件

QQ 机器人、微信公众号/企业微信、飞书/Lark、钉钉、Telegram、Discord、Slack、LINE、Matrix、IRC、MQTT、VK 等渠道均可配置。Pico WebSocket 与 Launcher 只是可选的控制台入口。

为什么不用自建前端

  • 消息、图片、文件都走已有聊天客户端
  • 会话、记忆、工具调用由网关统一处理
  • 需要桌面管理时再启动 Launcher
  • 多端、多人、群聊按渠道天然隔离
QQ / 微信 / 飞书 / 钉钉→ PicoClaw Gateway→ Agent + 工具→ SQLite 记忆→ 模型服务

记忆链路

每轮对话只做一次轻量抽取；写入前完成去重和冲突检查，注入时按预算和渠道筛选。

用户消息→规则抽取→去重 / 冲突→SQLite→审核→按需注入 
# 自动抽取修复：普通聊天不再写入记忆
# 只有明确“记住”、称呼、偏好、生日、日期事件才会抽取
picoclaw memory audit
picoclaw memory render  # 可选导出，不会被运行时读回

返回性能

流式中间帧限流；最终帧先于持久化发送；WebSocket 写超时；会话 JSONL 批量异步落盘。

首帧快

本地 Pico WebSocket 首帧通常在 1ms 内，主要延迟来自模型。

收尾短

最终帧不再等待 session 保存和上下文压缩。

连接复用

Provider HTTP 连接池，减少反复 TLS 握手。

并发修复

异步子任务、渠道关闭、会话读取的数据竞争已处理。

定时任务与提醒

Agent、CLI 和聊天渠道共享同一任务库；CLI 修改会自动同步到运行中的 gateway，错过的一次性任务会在启动后补执行。

Schedule

提醒与周期任务

一次性提醒、固定间隔和 cron 表达式，统一持久化在 workspace/cron/jobs.json。

Reliability

错过也会补执行

停机期间到期的一次性任务在启动后立即执行；失败任务保留错误状态，可重新启用重试。

Delivery

三种执行模式

Agent 推理、--deliver 直接发送、Shell 命令；CLI 修改约 1 秒内同步。
