# Migrating from 0.4.x to 0.5.x

0.5 upgrades the SQLite memory store to schema v2. There is no configuration change and no manual SQL step. The first time a 0.5.x launcher or gateway opens the database, it creates a `VACUUM INTO` backup and upgrades the schema in place. The data migration runs from `/memory` → “Database migration”, or with `picoclaw memory migrate`.

## What changes

- `entries` gains `facet`, so multiple facets under the same `subject+predicate` can coexist.
- `personas` uses `(id, version)` and gains `realm / audience / scope`, so a companion persona can stay private.
- `relationship_state` gains `expires_at`; old values are archived in `relationship_state_history`.
- Empty predicates become `待分类`; the reference v13–v21 relationship entries are mapped to predicate/facet and stay active.

## Upgrade

1. Stop the gateway and launcher.
2. Back up the workspace:
   ```bash
   cp -a ~/.picoclaw/workspace ~/.picoclaw/workspace.backup-$(date +%F)
   ```
3. Start 0.5.x and open `http://localhost:18800/memory` → “Database migration”.
4. Run the migration. CLI equivalent:
   ```bash
   picoclaw memory migrate
   ```
5. Verify:
   ```bash
   sqlite3 ~/.picoclaw/workspace/memory/memory.db "PRAGMA integrity_check;"
   ```
   Also check that a public channel cannot see a `fictional/private` persona.

The migration is idempotent and writes a new `memory.db.backup-*` file each time. It only changes classification; it never deletes entries.
