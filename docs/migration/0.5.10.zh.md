# 从 0.3.x / 0.4.x 迁移到 0.5.10

0.5.10 把 SQLite 记忆库升级到 schema v3。没有配置变更，也不需要手写 SQL。0.5.10 的 launcher 或 gateway 首次打开数据库时，会先做 `VACUUM INTO` 备份，再原地升级 schema；数据迁移在 `/memory` → “数据库迁移”执行，或运行 `picoclaw memory migrate`。

一键迁移同时覆盖 v1 和 v2 数据库：

```text
v1（0.3.x / 早期 0.4.x）→ v2（0.4.x / 0.5.0）→ v3（0.5.10）
```

## 变化

- `entries` 增加 `event_time_precision`、`event_timezone`、`event_time_source`、`valid_from`、`valid_to`、`pinned_core`。
- `sources` 升级为证据记录：`evidence_text`、`confidence`、`user_confirmed`、`message_id`、`extraction_model`、`prompt_version`；保留 v2 唯一键。
- 新增 `memory_relations`（关系边）、`memory_operations`（治理日志）、`memory_clusters` / `memory_cluster_members`（场景胶囊）、`memory_summary_versions`（为后续摘要预留）。
- FTS5 索引 `subject/predicate/facet/value/text`。没有 trigram 时记录 `unicode61`；完全没有 FTS5 时记录 `none`，数据库仍可打开。
- 空 predicate 统一为“待分类”；未知 predicate 的原值保留在 `attributes.original_predicate`。
- 参考库的 9 条 relationship 与 14 条 `待分类` 会归位；被误存为真实画像的台词会改判；被误归档的生日条目会恢复；缺失来源会补齐。
- 孤儿 sources 与断链 supersedes 的数量写入 `meta.v3_dropped_orphan_sources` / `meta.v3_dropped_orphan_supersedes`，不再静默丢弃。

## 升级

1. 停止 gateway 和 launcher。
2. 备份 workspace：
   ```bash
   cp -a ~/.picoclaw/workspace ~/.picoclaw/workspace.backup-$(date +%F)
   ```
3. 启动 0.5.10，打开 `http://localhost:18800/memory` → “数据库迁移”。
4. 执行迁移。命令行等价操作：
   ```bash
   picoclaw memory migrate
   ```
5. 验证：
   ```bash
   sqlite3 ~/.picoclaw/workspace/memory/memory.db "PRAGMA integrity_check;"
   picoclaw memory audit
   ```
   同时检查公开渠道是否看不到 `fictional/private` 伴侣人设。

迁移是幂等的，每次都会生成新的 `memory/backups/memory.db.bak-*` 备份并只保留最新 2 份；只改分类和新增结构，不删除条目。

## 说明

- v0.4.6 tag 仍然保留；安装 0.5.10 才能获得 schema v3 和 Launcher 迁移页。
- 历史 0.3.x → 0.4.0 迁移：[0.4.0.zh.md](0.4.0.zh.md)。
- `MEMORY.md` 只作为导入源，运行时永远不会被读取。
- `memory forget` 是硬删除；先不带 `--yes` 运行可以看到级联影响预览。
