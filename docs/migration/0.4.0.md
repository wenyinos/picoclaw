# Migrating from 0.3.x to 0.4.0

0.4.0 replaces the free-form `MEMORY.md` runtime with a SQLite memory database. There is no automatic schema migration: the database is the source of truth, and the old Markdown file is only an import source.

## Before you start

- Stop the gateway and launcher.
- Back up the entire workspace. This is not a compatibility mechanism, only a safety net.
- Keep the old workspace until `picoclaw memory audit` reports the expected entries.

```bash
systemctl --user stop picoclaw picoclaw-launcher
cp -a ~/.picoclaw/workspace ~/.picoclaw/workspace.backup-$(date +%F)
```

## Option A: keep the existing workspace and import

```bash
picoclaw memory import --from ~/.picoclaw/workspace
picoclaw memory render
picoclaw memory audit
```

The importer:

- folds repetitive legacy task templates;
- skips trivial chit-chat;
- archives failed task records;
- imports session summaries as `pending_review` episodic memories;
- converts old `MEMORY.md` bullets into `pending_review` profile candidates.

## Option B: replace with a prepared 0.4 workspace

```bash
rm -rf ~/.picoclaw/workspace
tar -xzf picoclaw-workspace-0.4-portable.tar.gz -C ~/.picoclaw
chown -R <service-user>:<service-group> ~/.picoclaw/workspace
```

The archive contains a ready `workspace/` directory with `memory/memory.db` and `sessions/`. It does not contain machine-specific absolute paths.

## Configuration

Use a relative workspace so the same directory can move between machines and users:

```json
{
  "agents": {
    "defaults": {
      "workspace": "workspace"
    }
  }
}
```

`workspace` is resolved against `PICOCLAW_HOME`. Absolute paths still work.

0.3.x configs do not need a `memory` section; 0.4 applies these defaults while loading:

```json
{
  "memory": {
    "enabled": true,
    "db_path": "memory/memory.db",
    "budget_tokens": 1200,
    "auto_extract": true,
    "private_channels": ["pico"],
    "inject_fictional": false,
    "review_required": true,
    "episodic_retention_days": 365
  }
}
```

## Start and review

```bash
systemctl --user start picoclaw picoclaw-launcher
```

Open `http://localhost:18800/memory`:

- Confirm real user facts.
- Mark role-play or fictional settings as `fictional`.
- Mark reusable procedures as `work`.
- Archive expired events and noise.

Pending entries are not injected into prompts, so review is part of the migration.

## Copying a workspace

`memory.db` is SQLite in WAL mode. Ensure no process is using it before copying:

```bash
systemctl --user stop picoclaw picoclaw-launcher
picoclaw memory audit      # opens/closes the store and checkpoints an idle WAL
cp -a ~/.picoclaw/workspace /target/path/
```

Only `memory/memory.db` is required; `-wal` and `-shm` files can be discarded after a clean shutdown.

## Rollback

If you need to return to 0.3.x, stop the services and restore the backup workspace. Do not point 0.4 at an old `MEMORY.md` and expect it to be read; import the file first.
