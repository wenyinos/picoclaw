# 从 0.4.x 迁移到 0.5.x

0.5 把 SQLite 记忆库升级到 schema v2。没有配置变更，也不需要手写 SQL。0.5.x 的 launcher 或 gateway 首次打开数据库时，会先做 `VACUUM INTO` 备份，再原地升级 schema；数据迁移在 `/memory` → “数据库迁移”执行，或运行 `picoclaw memory migrate`。

## 变化

- `entries` 增加 `facet`，同一 `subject+predicate` 下的多个侧面可以共存。
- `personas` 改成 `(id, version)`，并增加 `realm / audience / scope`，伴侣人设可以只进私有渠道。
- `relationship_state` 增加 `expires_at`；旧值归档到 `relationship_state_history`。
- 空 predicate 统一为“待分类”；参考库 v13–v21 的 relationship 条目会写入 predicate/facet 并保持 active。

## 升级

1. 停止 gateway 和 launcher。
2. 备份 workspace：
   ```bash
   cp -a ~/.picoclaw/workspace ~/.picoclaw/workspace.backup-$(date +%F)
   ```
3. 启动 0.5.x，打开 `http://localhost:18800/memory` → “数据库迁移”。
4. 执行迁移。命令行等价操作：
   ```bash
   picoclaw memory migrate
   ```
5. 验证：
   ```bash
   sqlite3 ~/.picoclaw/workspace/memory/memory.db "PRAGMA integrity_check;"
   ```
   同时检查公开渠道是否看不到 `fictional/private` 伴侣人设。

迁移是幂等的，每次都会生成新的 `memory.db.backup-*` 备份；只改分类，不删除条目。
