# 从 0.3.x 迁移到 0.4.0

0.4.0 使用 SQLite 记忆库替代自由文本 `MEMORY.md`。**没有自动 schema 迁移**：数据库是唯一事实源，旧 Markdown 只作为一次性导入源。

## 迁移前

- 停止 gateway 和 launcher。
- 备份整个 workspace。这不是兼容机制，只是回滚保险。
- 保留旧 workspace，直到 `picoclaw memory audit` 显示预期条目。

```bash
systemctl --user stop picoclaw picoclaw-launcher
cp -a ~/.picoclaw/workspace ~/.picoclaw/workspace.backup-$(date +%F)
```

## 方案 A：保留现有 workspace 并导入

```bash
picoclaw memory import --from ~/.picoclaw/workspace
picoclaw memory render
picoclaw memory audit
```

导入器会：

- 折叠重复的旧任务模板；
- 跳过普通闲聊；
- 归档失败的任务记录；
- 把会话摘要导入为 `pending_review` 事件记忆；
- 把旧 `MEMORY.md` 条目转换为 `pending_review` 用户画像候选。

## 方案 B：替换为准备好的 0.4 workspace

```bash
rm -rf ~/.picoclaw/workspace
tar -xzf picoclaw-workspace-0.4-portable.tar.gz -C ~/.picoclaw
chown -R <service-user>:<service-group> ~/.picoclaw/workspace
```

归档内包含可直接使用的 `workspace/`，其中有 `memory/memory.db` 和 `sessions/`，不包含机器相关的绝对路径。

## 配置

建议使用相对 workspace，方便跨机器、跨用户迁移：

```json
{
  "agents": {
    "defaults": {
      "workspace": "workspace"
    }
  }
}
```

`workspace` 按 `PICOCLAW_HOME` 解析；绝对路径仍然可用。

0.3.x 配置不需要手动添加 `memory` 节，0.4 加载时会自动补默认值：

```json
{
  "memory": {
    "enabled": true,
    "db_path": "memory/memory.db",
    "budget_tokens": 1200,
    "auto_extract": true,
    "private_channels": ["pico"],
    "inject_fictional": false,
    "review_required": true,
    "episodic_retention_days": 365
  }
}
```

## 启动并审核

```bash
systemctl --user start picoclaw picoclaw-launcher
```

打开 `http://localhost:18800/memory`：

- 确认真实的用户事实；
- 把角色扮演或虚构设定标记为 `fictional`；
- 把可复用流程标记为 `work`；
- 归档过期事件和噪声。

待审核条目不会进入提示词，审核是迁移流程的一部分。

## 复制 workspace

`memory.db` 是 WAL 模式的 SQLite。复制前确保没有进程正在使用：

```bash
systemctl --user stop picoclaw picoclaw-launcher
picoclaw memory audit      # 打开/关闭空闲库并完成 WAL checkpoint
cp -a ~/.picoclaw/workspace /目标路径/
```

干净关闭后只需要 `memory/memory.db`，`-wal` 和 `-shm` 可以丢弃。

## 回滚

如需回到 0.3.x，停止服务并恢复备份 workspace。不要指望 0.4 读取旧 `MEMORY.md`；如需保留内容，请先导入。
