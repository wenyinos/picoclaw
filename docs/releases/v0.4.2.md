# PicoClaw 0.4.2

0.4.2 移除了旧 Markdown 记忆的运行时兜底，让 SQLite 记忆库成为唯一记忆源。

## 变更

- 运行时不再读取 `MEMORY.md`、每日笔记或其他 Markdown 记忆文件。
- `memory.enabled: false` 或 SQLite 不可用时，不再回退到文件记忆，而是完全不注入长期记忆。
- 系统提示不再要求模型更新 `MEMORY.md`；启用 SQLite 记忆时，模型改用 `memory` 工具保存、搜索和遗忘记忆。
- 默认 workspace 提示不再列出 `MEMORY.md` 和每日笔记路径。
- 删除旧 `MemoryStore`，`MEMORY.md` 不再参与系统提示缓存失效。
- 新增回归测试：即使 workspace 中存在 `MEMORY.md` 和每日笔记，它们也不会进入系统提示。

## 升级

- 无配置或数据库结构变更。
- 安装 0.4.2 二进制并重启 gateway。
- 可以直接删除 `workspace/memory/MEMORY.md`。运行时不会读取，也不会自动重建。
- 如果仍需要旧文件中的事实，请先执行一次 `picoclaw memory import --from /path/to/old-workspace`，确认 `pending_review` 条目后再删除。
- `picoclaw memory render` 仍可手动生成 Markdown 导出，但导出结果不会被运行时读回。

## 构建

直接调用 Go 时请带上项目构建标签：

```bash
CGO_ENABLED=0 go build -tags goolm,stdjson ./...
```

`goolm` 选择 mautrix 的纯 Go 加密实现；缺少它时默认走 libolm，需要 CGO 和系统 libolm。`make build` 已包含这些标签。
