# PicoClaw 0.6.0

0.6.0 新增**全局系统提示词**：在 Launcher 里切换一次，微信、QQ、WebSocket、pico 等所有渠道统一按新指令运行。不涉及数据库变更，`config.json` 结构不变。

## 新增

### 全局系统提示词

Launcher 侧边栏新增「系统提示词」页面，可以维护多套预设，并随时指定哪一套生效。

- **一处切换、全渠道生效**：保存后从下一个对话轮次起，所有渠道统一使用新指令；无需重启 gateway，也无需重新加载配置。
- **可维护多套预设**：最多 10 套，单条指令上限 8000 字符。适合「工作模式 / 闲聊模式」这类常用切换。
- **总开关**：关闭后不注入任何自定义指令，行为与未配置时完全一致。
- **编辑前先看清边界**：页面底部标注了存储路径，并说明自定义指令无法突破代码层限制（如 `restrict_to_workspace`、exec 命令白名单）。

### 实现方式

配置存放在 `~/.picoclaw/instructions.json`（权限 `0600`），与 `config.json` 分离：

- 该文件参与既有的 mtime 缓存失效检查，因此改动会在下一次构建系统提示词时自动生效，没有引入新的热重载通道。
- 指令内容合并进 `instruction.workspace` 同一个 PromptPart，提示词分层顺序与缓存序列保持不变。
- 文件缺失、JSON 损坏或 `active` 指向不存在的预设时，静默降级为「不注入」，并记录一条 warn 日志，不会中断对话。

### API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/instructions` | 读取当前配置、存储路径与上限 |
| PUT | `/api/instructions` | 校验后原子写入，非法载荷返回 400 |

两个端点沿用 dashboard 会话鉴权，未额外开放权限。

## 修复

- `TestMemoryAPI_MigrationStatusAndApply` 原先硬编码 schema 版本 2，改为引用 `memstore.CurrentSchemaVersion`，不再随 schema 升级而失效。

## 升级

- **无数据库变更，无配置迁移。** 不新增、不修改 `config.json` 字段。
- `instructions.json` **不会自动创建**，首次在页面点击保存时才写入。未配置前，系统提示词与 0.5.x 逐字节一致。
- 更新 launcher 二进制并重启即可；已完成配置的用户，该文件位于 `~/.picoclaw/`，升级不会覆盖。
- **容器部署注意**：`docker/docker-compose.full.yml` 只挂载 `config.json` 与 `workspace`，`instructions.json` 会落在容器可写层。请额外持久化该文件所在目录，否则重建容器会丢失配置（`workspace` 内的会话与记忆不受影响，问题不易察觉）。
