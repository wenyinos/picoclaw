# PicoClaw 0.7.4

0.7.4 修复 0.7.3 的一个启动阻断缺陷，属于紧急补丁。

## 缺陷

配置加载使用严格的未知字段校验。0.7.3 删除了 `memory.private_channels` 字段，于是所有由 0.7.2 及更早版本写入、仍带有该字段的 `config.json` 在 0.7.3 下都无法加载：

```text
Failed to load config: config.json contains unknown field(s): memory.private_channels
```

gateway 随之无法启动，systemd 不断重启，部署表现为反复重启、完全不可用。

## 修复

- 恢复 `private_channels` 字段定义并标记 Deprecated：旧配置文件恢复可加载。
- 该字段在加载时被清空并记录一条告警；0.7.3 的语义（默认全渠道私密、`private_channel_exclusions` 排除制）完全不变。
- 新增回归测试：带旧字段的配置必须能加载，字段清空，排除列表不受影响。

## 升级

1. 无 Schema 变更，覆盖二进制后重启 launcher 即可。
2. 如果你在排障时手动删除过 config.json 里的 `private_channels` 行，无需恢复，两种状态都能启动。
3. 验收：`systemctl --user status picoclaw-launcher` 稳定 active、不再出现 unknown field 错误、QQ 会话 `memory search` 命中旧记忆。

## 已知边界

- 外部 LLM 抽取、向量/语义召回仍未接线，保持默认关闭。
- 群聊专属记忆域预留未启用。
