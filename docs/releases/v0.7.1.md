# PicoClaw 0.7.1

0.7.1 补齐 V4 计划中三项收尾：实际发送点门禁、跨存储清理执行器、前端治理工作台。无 Schema 变更，直接覆盖安装即可。

## 新增

- **发送点门禁**：`memory.allowed_chat_recipients` 白名单会在每次实际模型请求前检查，包括主调用、fallback 候选和流式调用。未列入的 provider 返回不可重试的 `memory egress denied`，不会被自动改投到另一个云端。
- **跨存储清理执行器**：`forget` 在与删除相同的主库事务内写入 `forget_cleanup` 任务，manifest 记录来源消息定位和证据 HMAC（不保存正文）。`picoclaw memory cleanup` 消费任务，对 JSONL 会话按精确内容匹配删除；无法验证时如实报告 `unavailable/partial`。
- **治理与运行页**：Launcher `/memory` 新增页签，展示遗忘账本健康与待清理义务、待审批的变更计划、后台任务统计、记忆域、承诺和阶段摘要；支持批准计划、重放账本、生成摘要。

## 修复

- 清理任务与遗忘义务同事务提交，崩溃后不会丢失跨存储清理目标。
- 清理 worker 只消费 `forget_cleanup`，不会误取抽取或摘要任务。

## 升级

1. 0.7.1 不修改 schema，仍是 v4；从 0.7.0 升级无需迁移。
2. 可选：在 `config.json` 的 `memory.allowed_chat_recipients` 中列出 `provider` 或 `provider/model` 以启用接收方白名单；留空保持 0.7.0 行为。
3. 运行 `picoclaw memory cleanup` 处理升级前遗留的清理义务。

## 已知边界

- JSONL 清理只做“内容完全匹配”的精确删除；消息被编辑或改写后无法证明对应关系，会报告 partial。
- 外部 LLM 抽取与向量/语义召回仍未接线，保持默认关闭。
- 助手复述形成的历史文本尚未做逐轮污点追踪，属于完整发送链路治理的后续工作。
