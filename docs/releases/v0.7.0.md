# PicoClaw 0.7.0

0.7.0 是记忆系统的 V4 升级：把“可存储、可检索”推进到“可信、可治理、可遗忘”。数据库只做一次 `v3 → v4` 迁移，旧的 v1 → v2 → v3 迁移链已删除。

## 新增

- **schema v4**：新增归属域（`memory_domains`）、渠道绑定（`memory_actor_bindings`）、处理用途许可（`memory_processing_grants`）、来源事件（`memory_origin_events`）、依赖表（`memory_dependencies`）、持久任务（`memory_jobs`）、审批计划（`memory_change_plans`）、承诺（`memory_commitments`）、主动回忆（`memory_recalls` / `memory_recall_feedback`）和摘要证据（`memory_summary_evidence`）。
- **独立遗忘账本** `memory/forget-ledger.db`：`forget` 先写 journal（HMAC 选择器、目标清单、request_id），再改主库；恢复旧备份后仍可由账本重放，已遗忘内容不会复活。
- **遗忘联动关系状态**：删除称呼/生日/情绪条目时同步清理 `relationship_state` 与历史，固定注入块不再残留被遗忘的称呼。
- **域内去重**：精确指纹索引改为 `(domain_id, content_hash)`；模板折叠、近重合并、自动标量替换全部限定在同一域，不同权限域的同文记忆独立保留。
- **统一服务层**：`MemoryService` 提供授权读写与一次性变更计划；批准时校验目标 revision，过期或已变更的计划返回冲突。模型工具只能预览永久遗忘，不能自批。
- **检索正确性**：权限在 `LIMIT` 之前进入 SQL；长查询保留 LIKE 回退；纯时间命中不再被丢弃；1-Hop 与主检索共享去重集合和层配额；预算计入分隔符与实际渲染文本。
- **阶段摘要与证据**：手工主题/阶段簇、逐 claim 绑定 evidence、`generation` 递增失效；遗忘或纠错会让依赖摘要立即不可见。默认本地规则摘要器，不调用外部模型。
- **承诺与主动回忆**：承诺生命周期 `proposed → confirmed → fulfilled/cancelled`，到期不会自动判违约；主动回忆默认关闭，需要私密目标、每日上限与主题冷却。
- **持久任务队列**：租约、重试退避、attempts 上限后进入 `blocked`，已接受的遗忘/清理任务不会被容量淘汰。
- **Web/API**：新增 inspect、correct、forget（支持 dry-run）、域、账本健康/重放、簇/摘要/证据、承诺、回忆反馈、任务、计划审批等接口；前端 API 客户端同步接线。
- **配置开关（默认关闭）**：敏感采集、摘要、LLM 抽取、语义召回、主动回忆、接收方白名单等，缺失字段保持安全默认。

## 修复

- `memory` 工具使用真实请求渠道上下文，胶囊不再选择“配置里的第一个私密渠道”；缺少渠道上下文时拒绝敏感操作。
- `PUT /api/memory/entries/{id}` 的正文变化转为版本化 `Correct`；`pinned_core` 条目在无 `force` 时拒绝正文/受众/作用域变更。
- 来源重建逐字段保留证据原文、模型、prompt 版本、置信度、确认标志与 `message_id`，不再在自愈时丢失。
- 关系状态支持 TTL 三态（保留/清除/设置），编辑不再静默清除原到期时间。
- 情绪抽取测试改用可控时钟，不再依赖运行日期。

## 升级

1. 停止 gateway 和 launcher。
2. 备份 workspace；`forget-ledger.db` 一旦存在必须一起备份。
3. 确认 `memory.db` 的 `schema_version` 为 3。v1/v2 数据库先用 0.6.x 打开一次。
4. 启动 0.7.0，打开 `http://localhost:18800/memory` → “数据库迁移”，或运行 `picoclaw memory migrate`。
5. 迁移先做 `VACUUM INTO` 备份，逐字段重建 `sources`，建立隔离域 `legacy_unassigned`，最后写 `schema_version=4`。重复执行安全。
6. 0.6.x 二进制禁止写 v4 数据库；回滚必须离线恢复备份并重放最新账本。
