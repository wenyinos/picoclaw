# PicoClaw 0.7.10

0.7.10 是一次安全与治理修复版本，关闭符合性评估中剩余的 P0/P1 缺口。没有 Schema 变更，仍为 v4。

## 背景

0.7.x 的 schema、迁移、账本和治理基础已经存在，但评估发现若干入口没有共享同一套可信上下文：群聊可以经提示词或工具读取私密记忆，模型工具可以绕过 `MemoryService`，普通单 Provider 主调用没有经过发送点门禁，账本缺失时会静默新建，FTS/LIKE 的权限过滤晚于候选上限，`Correct` 与摘要失效也不是单事务。0.7.10 按报告逐项修复，行为不确定的部分保持现有实现。

## 安全与隐私

- **群聊读取收紧**：提示词固定块（画像、边界、关系状态、persona）、检索块和 `memory` 工具统一使用可信 chat kind。群聊/公开会话只接收 `audience` 为空或 `all` 的内容，即使渠道未被 `private_channel_exclusions` 排除。
- **工具统一治理**：`memory` 工具的写入、确认、纠正、归档/恢复、遗忘预览和关系状态更新都经过 `MemoryService`；共享聊天不能写个人长期记忆，模型不能自批永久遗忘。
- **秘密禁入**：`Store.Add` 成为不可绕过的存储层约束，密码、验证码、API Key、私钥不再能通过工具、API、自动抽取或导入落库。
- **发送点门禁**：主调用、每个 fallback 候选、重试和流式调用在真正发送前检查 `memory.allowed_chat_recipients`；未授权返回 `memory egress denied`。
- **日志脱敏**：debug 日志只记录 system prompt、消息正文和工具参数的长度与 SHA-256 前缀，不再写入原文。
- **文件权限**：数据目录 0700、主库 0600、备份目录 0700。

## 遗忘与账本

- 迁移/修复备份现在同时生成主库 `memory.db.bak-*` 与 `forget-ledger.db.bak-*` 的 `VACUUM INTO` 快照，二者使用同一时间戳并各自保留最新 2 份。
- 已有 v4 库的账本缺失、HMAC key 损坏或身份字段不完整时，记忆读取仍可用，但 `forget`/`replay-forget` 故障关闭；不再静默创建新账本或重置身份。
- 全新数据库和 v3 → v4 迁移允许创建第一份账本。
- 新增校验命令：

```sh
picoclaw memory ledger-verify --backup /path/to/forget-ledger.db.bak-<timestamp>
```

输出 `match: true/false`、备份与当前账本的 UUID/key_id；不一致时返回非零退出码。恢复旧主库时必须使用与该库匹配的最新有效账本，不能用其他实例的账本替代。

## 数据一致性

- `Correct` 在单事务内完成旧版本 supersede、新版本写入、supersede 边、操作日志和依赖摘要失效；新版本继承原条目的 `domain_id`、sensitivity 与 `pinned_core`。
- 审批计划用 `pending → executing → executed/failed` 原子 claim，重复批准不会重复执行；补齐 `set_relationship` 的创建与执行。
- 摘要发布校验预期 `generation` 与 cluster 成员，证据写入真实 `source_id`；内容、受众、作用域或状态变化在同一事务内失效依赖摘要。
- `cleanup` 对无 locator 或存在 `unavailable` 的任务标记 `blocked`，不再以 `done` 表示完整清除；gateway 启动时和每 5 分钟自动消费 `forget_cleanup`。
- 导出分页读取全部条目，不再被 `Store.List` 的 100 条上限截断。
- 承诺创建不允许直接进入 `fulfilled`/`cancelled`。

## 升级

1. 无 Schema 变更，无配置字段变更；覆盖二进制并重启 launcher/gateway。
2. 首次启动会自动处理遗留的 `forget_cleanup` 任务；无法核验 JSONL 内容的任务会显示 `blocked`，需要人工处理。
3. 如果已有 v4 库缺少 `forget-ledger.db`，请先从备份恢复匹配的账本，再执行 `ledger-verify`；在账本恢复前永久遗忘会故障关闭。
4. 群聊读取会立即收紧：此前可能注入群聊的私密画像/边界/关系状态将不再出现，这是预期行为。

## 验证

```sh
go test -tags 'goolm stdjson' ./pkg/memstore ./pkg/agent ./pkg/tools \
  ./pkg/tools/shared ./pkg/identity ./pkg/session ./pkg/memory \
  ./pkg/seahorse ./pkg/config ./web/backend/api -count=1 -timeout=300s
cd web/frontend && pnpm run lint && pnpm run build
```

新增回归覆盖：群聊提示词与工具读取、工具写入治理、秘密禁入、单 Provider 发送门禁、账本缺失/损坏、账本备份与校验、FTS/LIKE 权限前置、Correct 继承与摘要失效、摘要 generation/成员/source、cleanup blocked、导出分页。

## 已知边界

- 外部 LLM 抽取、embedding/向量检索、MMR、主动投递调度仍未接线，保持默认关闭。
- Seahorse 逐条消息/摘要清理仍未实现，相关任务会保持 `partial`/`blocked`。
- 账本恢复是人工流程；本版本提供备份与 identity 校验，不自动合并不同账本。
- 归属域仍以 `legacy_unassigned` 为主；0.7.10 不猜测 owner，也不自动认领历史数据。
