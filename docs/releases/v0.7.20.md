# PicoClaw 0.7.20

0.7.20 是一次记忆安全、恢复与清理修复版本。没有 Schema 变更，仍为 v4；重点关闭墓碑复活、模型越权、跨会话读取、发送点漏检、清理误报和恢复流程中的假成功。

## 背景

0.7.10 已经有域、账本、摘要证据和主聊天 egress 的基础，但完整审计发现：`Correct` 能绕过遗忘墓碑；模型仍可自批和修改核心状态；写入 API 可反序列化内部治理字段；Seahorse 工具缺少会话约束；后台摘要、`/btw` 和子代理仍有未覆盖发送点；JSONL 清理无法匹配长证据和工具参数；Seahorse 没有逐条清理；迁移修复可能先改库后备份。0.7.20 按实施计划逐项修复，并用回归测试锁定。

## 安全与权限

- **墓碑不可复活**：`Correct` 对新正文执行与 `Add` 相同的账本和主库墓碑检查；`BypassForgetTombstone` 不再是公开 API 可用路径。
- **模型治理收口**：模型只保留 `add / search / inspect / 非核心 correct / legacy capsule / forget 预览`。`confirm`、归档/恢复、所有关系状态写入，以及任何 force/pinned/boundary 变更均返回 owner-only；模型不能创建可执行计划。
- **写入 DTO**：记忆条目 API 使用白名单结构并严格拒绝未知字段；`Force`、`ForceStatus`、domain、来源根、origin/session/message 身份等字段只能由宿主生成。
- **秘密分类扩展**：增加 `password/passwd/bearer/client_secret/refresh_token/access_token`、常见 `sk-`、`ghp_`、GitHub PAT、Slack token 与 PEM 私钥模式；关系状态也执行同一分类和长度上限。
- **审计身份**：新操作记录宿主派生的 actor、完整 request ID、reason code 和 policy revision；dashboard actor 明确表示“该安装实例的 owner 入口”，不伪造个人 principal。
- **审批计划**：创建仅限 owner；参数移除内部字段；批准时重新校验 payload digest、domain 和 entry revision；claim 时立即保存批准人；`blocked` 计划只能生成新预览后显式 requeue，过期计划清空 payload。

## 读取隔离与外发

- **Seahorse 会话隔离**：`short_grep`/`short_expand` 使用可信 `AgentID + sessionKey` 解析唯一 conversation；缺身份、归属冲突或 conversation 不存在都拒绝。模型传入 `all_conversations=true` 直接报错。
- **未知 ChatKind fail-closed**：有聊天上下文但类型缺失/未知时按 public 处理；异步工具 follow-up 继承原 Channel/ChatID/ChatType/SessionKey，并禁止自动抽取。
- **完整发送点门禁**：主调用、fallback、重试、流式、`/btw`、legacy/Seahorse 摘要和 subagent legacy tool loop 都按用途与接收方检查。策略拒绝保留 `ErrMemoryEgressDenied`，不 retry、不静默 fallback，Provider 调用为 0。
- **关闭记忆不等于停止清理**：`memory.enabled=false` 不再阻止已接受 forget cleanup；会话派生内容的摘要仍按 recipients 检查，不能被 budget=0 或 enabled=false 绕过。
- **日志去正文**：agent DEBUG 请求日志与响应日志不再包含完整消息、reasoning 或工具参数，只记录数量与摘要指纹。

## 遗忘与恢复

- **来源根证据**：宿主在入站/工具边界生成版本化 `evidence_root`（v/algo/key_id/type/canonicalization/digest），每个 `origin_event_id` 对应一个完整来源单元；公开 API 不能伪造。
- **JSONL 原子清理**：新增会话级 `MutateHistory`，在同一 shard 锁内 flush→读取→验证→重写；不再由外部 GetHistory/SetHistory 组合产生竞争。清理删除所有验证重复项，并支持完整 Content、重复消息和工具调用文本。
- **Seahorse 精确清理**：新增按 conversation/message/part 的事务删除；同时处理 message_parts、context_items、summary_messages，并递归删除依赖该消息的 summary 与父摘要。Ingest/Compact/Clear/新清理共用 per-conversation 锁，异步 condensed compaction 也重新取得同一锁。
- **Replay 按域和清单**：不再全库按来源哈希删除；只按账本 manifest 的 entry IDs + domain 重放，读取全部 intent，并把 cleanup 重新入队。`replay-forget` 默认 dry-run，`--yes` 才执行。
- **历史审计**：新增 `picoclaw memory forget-audit`，只输出历史 forget 的 ID/hash/时间/是否仍存在/域信息，不删除、不补写账本。
- **摘要正文清除**：遗忘时清除 summary 与 claims、summary evidence、dependencies，而不只是把状态改为 invalidated；需要重建时在事务外进行。
- **清理状态**：新增 `already_absent`、`outcome_unknown` 字段与任务详情；CLI 在 `unavailable/outcome_unknown` 时返回非零，不再把 removed=0 当成完成。

## 数据库迁移与恢复

- **原子新库初始化**：base+v4 表、治理列、索引、FTS、默认域、revision 和 `schema_version` 在同一事务完成；`loadRevision` 不再提前写入假 v4。
- **完整性计划**：必要表和唯一索引纳入检查；v4 缺业务/义务/审计表时返回 `non_repairable`，必须恢复备份，不创建空表。
- **先备份再修改**：迁移、v4 修复和显式维护在实际写入前生成主库与账本快照；`RepairData` 不再先改库后备份。备份路径失效时会重新生成，不信任空 meta。
- **账本并发身份**：账本连接使用 `_txlock=immediate`，身份创建在立即事务内二次检查，多个进程同时首次打开只产生一个 UUID/HMAC key。
- **账本幂等**：相同 request ID 返回既有 intent；不同内容复用同一 request ID 返回冲突。
- **备份水位**：`ledger-verify` 输出 backup/active max seq、applied seq、pending 数量以及 identity/watermark 比较。
- **数据库迁移页**：空 predicate 不再造成永久“需要迁移”提示，只作为数据质量提示；文案不再声称无变更也会重新备份。

## 检索、预算与配置

- **TTL 与层策略前置**：普通 Search、FTS/LIKE、时间、1-hop、固定 profile/boundary 和 capsule 在 SQL/LIMIT 前过滤过期、audience、domain 与 layer；1-hop 不再绕过主检索的 layer 策略。
- **固定上下文**：profile/boundary 的 audience 过滤进入 SQL，private 行不会先占满 40/30 条再挤掉 public sentinel。
- **预算**：基础内容最多使用固定目标预算的 70%，剩余给边界与检索；固定块耗尽时 retrieval=0，不再强制 200 token。核心 boundary 不静默丢弃，溢出/裁剪通过 `FixedUsage` 暴露。
- **设置合并**：`PUT /api/memory/settings` 改为字段存在性合并，缺省 recipients/V4 开关保持原值；`memory:null` 和只有 `db_path` 的部分配置保持安全默认。
- **关系状态**：写入增加长度上限、秘密分类和操作日志；当前单列主键不支持多域同名 key，非 legacy 写入明确拒绝。
- **危险删除绑定修订**：dashboard forget 默认预览；真实删除要求 `confirm=true` + `expected_revision`，revision 在 Store 锁内校验。CLI `forget --yes` 必须提供 `--expected-revision`。

## 前端与 CLI

- 记忆页区分“未 applied 账本意图”和 cleanup job 积压，展示 job state/attempts/last_error；Replay 前要求确认。
- 迁移页只把 schema 问题显示为迁移，空 predicate 单列为数据质量提示。
- 新增 `memory forget-audit`；`replay-forget` 默认 dry-run；`cleanup` 检测 gateway PID，覆盖 JSONL 与 Seahorse，partial/unknown 返回非零。
- CLI 记忆子命令新增危险参数和默认 dry-run 测试。

## 升级

- 无 Schema 变更（仍为 v4），无新增必需配置字段；覆盖二进制并重启 launcher/gateway。
- 模型工具行为收紧：`confirm`、归档/恢复和关系状态更新需要 owner 在 dashboard/CLI 执行。
- 已经存在的 `forget_cleanup` 任务会在启动后按新来源根规则重试；旧记录没有根证据时仍可能保持 `unavailable/blocked`，不会猜测删除。
- `replay-forget` 现在默认 dry-run；脚本必须加 `--yes`。
- `forget --yes` 脚本必须从预览取得 `--expected-revision` 并传入。
- 参考数据库或生产库的迁移、Replay、Cleanup 仍需用户显式执行；本版本不自动修改已有数据库。

## 已知边界

- 历史 forget 中缺少 domain 的无盐 content hash 不会自动转为账本义务；`forget-audit` 只报告。
- 自动对账“批准后主事务失败”的 pending ledger intent 仍需人工维护；本版本提供幂等记录与只读审计，不自动重放无 actor/批准的旧 intent。
- `outcome_unknown` 字段和后端语义已建立，但现有内置后端在无法区分“已删除”和“从未存在”时会保守返回 `unavailable/blocked`。
- 完整多域 relationship、多域 capsule、每 Agent 独立 Seahorse Engine、长文分块和时间抽取仍未接线。
- 外部 LLM 抽取、embedding/向量检索、MMR 和主动投递调度保持关闭。
- 前端 `pnpm run format` 的仓库既有 15 个无关文件格式告警仍在；本次只格式化变更文件，lint/build 通过。
