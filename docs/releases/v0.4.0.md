# PicoClaw 0.4.0

PicoClaw 0.4.0 围绕长期记忆与关系连续性构建：SQLite 记忆库、独立记忆控制台，以及可整体复制迁移的 workspace。

## 重点

- **SQLite 长期记忆**（`workspace/memory/memory.db`）：分层条目、精确/近似去重、冲突替代、来源追踪，以及关系/人格状态。
- **记忆控制台**（`/memory`）：概览、搜索编辑、审核队列、关系/人格编辑和设置。
- **人工审核**：不确定的记忆停留在 `pending_review`，审核通过前不会进入提示词。
- **真实与虚构隔离**：角色扮演设定与真实用户画像分开存储，默认隐藏。
- **私密渠道过滤**：亲密记忆只注入配置为私密的渠道。
- **可迁移 workspace**：不保存机器相关绝对路径；`agents.defaults.workspace` 支持相对路径并按 `PICOCLAW_HOME` 解析。
- **`picoclaw memory` CLI**：import、audit、stats、compact、export、render。
- **更快的返回路径**：Pico 中间帧限流、最终帧先于持久化、WebSocket 写超时、模型连接池复用、会话 JSONL 异步写入。
- **并发修复**：异步子任务交付、渠道关闭、会话 API 读取等数据竞争。

## 从 0.3.x 升级

0.4.0 **不会自动迁移 schema**。运行时记忆保存在 `memory.db`，旧的 `MEMORY.md` 不再被读取。

1. 停止 gateway 和 launcher。
2. 备份 workspace。
3. 执行 `picoclaw memory import --from <旧 workspace>`，或用准备好的 0.4 workspace 替换。
4. 执行 `picoclaw memory render` 和 `picoclaw memory audit`。
5. 启动服务，在 `/memory` 页面审核待确认条目。

完整说明：[从 0.3.x 迁移到 0.4.0](https://github.com/wenyinos/picoclaw/blob/main/docs/migration/0.4.0.md)。

## 不兼容变更

- 不再发布 Linux/mipsle 二进制：纯 Go SQLite 驱动不支持 MIPS32。
- `workspace/memory/memory.db` 成为长期记忆的唯一事实源。
- 旧 `MEMORY.md` 内容如需保留，必须导入一次。
- 复制或导入 workspace 时必须停止 gateway 和 launcher。
