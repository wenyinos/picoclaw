# PicoClaw 0.7.3

0.7.3 修复 0.7.2 之后报告的一类可见性故障：部署在 QQ 等渠道的会话升级后 `memory search` 零命中、旧 `private` 记忆读不到。根因是旧的私密渠道白名单；0.7.3 把语义反转为默认全选 + 手动排除。

## 修复

- **私密渠道排除制**：`audience=private` 的记忆默认对所有渠道可见；用 `private_channel_exclusions` 排除个别渠道。旧字段 `private_channels` 不再读取，升级后 QQ/微信等渠道立即恢复可见。
- **设置页复选框**：`/memory` → 设置新增「渠道记忆可见性」，默认全选，取消勾选即排除；API 返回 `available_channels` 供渲染。
- **群聊禁抽取**：群聊/公开会话的消息不再进入自动抽取，共享对话不写入个人画像；群聊读取仍只允许 `audience=all`，与渠道配置无关。
- **日志降噪**：删除 `allow_from` 为空的周期性安全警告；接入行为不变。

## 升级

1. 无 Schema 变更（仍为 v4），覆盖二进制后重启即可。
2. 旧配置中的 `private_channels` 被忽略；如某些渠道不应读取私密记忆，到设置页取消勾选。
3. 验收：QQ 中 `memory search` 锚词命中、旧 ID `memory inspect` 成功、`memory add` 写后立即可查、`load_capsule` 非空。

## 验证

- `go test -tags 'goolm stdjson' ./pkg/memstore ./pkg/tools ./pkg/config ./pkg/memory ./web/backend/api ./pkg/agent` 全绿。
- 新增用例：默认全渠道私密、排除生效、群聊拦截、群聊判定（direct/group/channel/public）。
- 前端 `pnpm run lint`（0 error）与 `pnpm run build` 通过。

## 已知边界

- 外部 LLM 抽取、向量/语义召回仍未接线，保持默认关闭。
- 群聊专属记忆域（按群建 `domain_id`）预留未启用：`EnsureDomain("group:qq:<群ID>")` 即可启用，零 schema 变更。
