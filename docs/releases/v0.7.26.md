# PicoClaw 0.7.26

0.7.26 是一次升级路径修复版本。主库 Schema 仍为 v4；重点是把 0.7.25 过于粗糙的恢复门禁收敛为「数据库修复」页里的一次性升级向导，让旧库升级后不再要求用户逐条手工处理历史阻塞。

> **重新发布说明（2026-11-28）：** 首次 0.7.26 发布后发现，`runRecoveryPreflight` 对进程级共享 Store 执行了 `Close`，导致网关启动预检结束后记忆工具报 `sql: database is closed`，且重启会重复触发。该版本已删除原 Release/tag 并用修复后的提交重新发布；同时向导结果新增 `restart_required` 与页面重启提示。旧资产不再作为 0.7.26 发布物使用。

## 背景

0.7.25 新增恢复门禁后，部分从 0.7.20 升级的数据库会出现：

- `default_domain_missing`：entries 使用 `legacy_unassigned`，但 `memory_domains` 缺少该默认域；
- `entries_without_domain`：上述 entries 被计为 orphan；
- `cancelled_cleanup_jobs`：历史 `forget_cleanup` 任务处于 cancelled，缺少可验证来源。

这些条件按故障关闭原则会关闭全部长期记忆。安全正确，但升级体验过重，且把可安全修复的域问题与不可验证的历史清理绑定成了全量停机。

## 一次性升级向导

入口：`/memory` →「数据库修复」→「一次性升级向导」。

流程：

1. 只读预览 Schema、默认域、orphan entries、历史 cleanup 任务和剩余阻塞；
2. 用户明确确认；
3. 强制备份主库与独立账本；
4. 需要时执行 v3 → v4，只恢复已知的 `legacy_unassigned` 默认域，不猜 owner；
5. 把历史 `cancelled/blocked/failed` cleanup 任务结案为 `legacy_closed`；
6. 记录 `legacy_cleanup_unverified` 操作审计；
7. 重新计算恢复门禁；
8. 返回 `restart_required=true`，页面提示重启 gateway/launcher。

`legacy_closed` 不表示来源副本已经验证删除，只表示历史义务不再阻塞长期记忆。结果保留 `residual_risk`、备份路径和强制重启提示。

向导不会自动结案以下状态：

- pending/running cleanup；
- pending/blocked ledger intent；
- 不支持或未来版本的 Schema；
- 账本不可用。

这些情况会明确列出阻塞原因，避免把新问题混入历史结案。

## 修复效果

对 0.7.20→0.7.25 常见的 131 条 legacy entries、缺失默认域和 2 条 cancelled cleanup：

- 默认域恢复后，131 条记忆不再被视为 orphan；
- 2 条历史 cancelled cleanup 结案为 `legacy_closed`；
- 恢复状态变为 ready，长期记忆不再被这些历史任务全局关闭；
- 备份、审计和残余风险在向导结果中可见。

## 测试与安全

- 新增升级预览/应用测试、默认域恢复测试、历史 cleanup 结案测试、未决 intent 拒绝结案测试。
- 新增“恢复预检不得关闭进程级共享 Store”回归测试；`OpenForWorkspace` 返回的缓存 Store 只由进程生命周期管理，预检不再关闭它。
- `legacy_closed` 是显式终态，不参与 pending/running/blocked 门禁，也不会被通用 Replay 或 requeue 当作已删除证明。
- 修复 `pkg/tools/shell_test.go`：URL 路径守卫测试改为直接调用 `guardCommand`，不再真实执行 `agent-browser open`、`curl`、`wget`、`git clone` 等命令，避免测试副产物启动后台浏览器/网络进程。

## 升级

- 主库 Schema 仍为 v4，不需要 v5。
- 覆盖二进制并重启 launcher/gateway。
- 打开 `/memory` →「数据库修复」，先看预览，再点击「一次性完成升级」。
- 向导自动备份主库和账本；备份路径显示在结果中。
- **向导完成后必须重启 gateway/launcher**；页面会返回 `restart_required=true` 并显示命令。数据库 ready 不等于运行中的 gateway 已重新加载记忆组件。
- 若仍有 pending/running cleanup、pending/blocked ledger intent 或不支持 Schema，向导不会伪造完成，需按提示单独处理。

## 已知边界

- `legacy_closed` 的历史来源副本可能仍然存在，报告中的 `residual_risk` 必须保留，不宣称已验证删除。
- 外部 LLM 抽取、embedding/向量检索、MMR、主动投递调度、完整多域 relationship、长文分块和时间抽取仍未接线。
- 完整 `MemoryUseManifest`、临时无记忆会话、来源编辑/撤回实时同步和历史 HMAC 轮换仍属后续工作。
- 当前向导只处理本地主库与账本；外部备份、导出、第三方渠道中已经存在的副本不在删除证明范围内。
