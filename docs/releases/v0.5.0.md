# PicoClaw 0.5.0

0.5.0 把长期记忆升级到 schema v2，并在 Launcher 的 `/memory` 页面提供一键迁移。这个版本面向已经有 0.4.6 记忆库的用户，迁移会先备份，不会删除条目。

## 新增

- 记忆库 schema v2：
  - `entries.facet`：同一 `subject+predicate` 下的不同侧面可以共存；
  - `personas (id, version)` 与 `realm / audience / scope`：人设支持多版本和渠道隔离；
  - `relationship_state.expires_at` 与 `relationship_state_history`：关系状态支持 TTL 和历史。
- Launcher `/memory` 增加“数据库迁移”页：查看 schema、空 predicate、relationship 数量，一键备份并迁移。
- 新增 API：`GET /api/memory/migration/status`、`POST /api/memory/migration/apply`。
- CLI 新增 `picoclaw memory migrate`。
- `memory` 工具支持 `subject`、`predicate`、`facet`、`value`、`supersedes_id`、`emotional_weight`、`valence`，以及 `update_state`。
- relationship 条目进入提示词检索候选，单次最多 2 条；命中后异步批量回写 `use_count/last_used_at`。
- 记忆库编辑器支持 predicate / facet；人格编辑器支持 realm / audience / scope。

## 修复

- persona 注入按渠道、realm 和 audience 过滤；`fictional/private` 伴侣人设不再进入公开渠道。
- `personas` 同 id 多版本不再撞主键。
- supersede 只对 profile 单值事实自动生效；其他层需要显式 `supersedes_id`，避免同一 predicate 的不同侧面互相覆盖。
- 空 predicate 统一为“待分类”；参考库 v13–v21 的 9 条 relationship 会写入 predicate/facet 并保持 active。
- 移除未使用的 `/api/memory/reindex` 空接口。

## 升级

- 无配置文件结构变更。
- 首次打开记忆库时会创建 schema v2 备份并升级 schema。
- 打开 Launcher `/memory` → “数据库迁移”，执行一次数据迁移；空 predicate 会变成“待分类”，可在记忆库中继续编辑。
- 迁移会先执行 SQLite `VACUUM INTO` 备份，只改分类，不删除条目。
