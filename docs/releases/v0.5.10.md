# PicoClaw 0.5.10

0.5.10 是记忆系统的 V3 升级：在 schema v2 之上补齐证据链、时间语义、治理闭环、关系网、场景胶囊和混合检索。v1 / v2 数据库仍然可以一键升级到 v3。

## 新增

- **schema v3**：`entries` 增加 `event_time_precision`、`event_timezone`、`event_time_source`、`valid_from`、`valid_to`、`pinned_core`；`sources` 升级为证据记录（`evidence_text`、`confidence`、`user_confirmed`、`message_id` 等）。
- **关系网**：新增 `memory_relations`，支持 `supersedes / contradicts / related_to / caused_by / influenced_by / fulfilled_by / next_scene / part_of`。
- **治理闭环**：新增 `memory_operations`，`memory` 工具支持 `inspect / confirm / correct / archive / restore / forget`。`forget` 会级联清理来源、关系、胶囊成员并使摘要失效，同时写入内容指纹，下一轮抽取不能把它复活。
- **时间语义**：确定性地解析今天/昨天/上周/上个月/去年夏天等短语，区分 `exact / date / approximate / range / planned / narrative`，近似时间不伪造单日。
- **场景胶囊**：`memory_clusters` + `memory_cluster_members`，`load_capsule` 一次取回 T0 写作铁律（完整版或紧凑版），公开渠道整体返回空。
- **混合检索**：Anchor → FTS → LIKE → 时间通道 → 1-Hop 关系扩展。两字中文查询自动走 LIKE，不再被 FTS5 trigram 的三字下限吞掉。
- **真实预算记账**：固定块、边界块、检索块分别计数；`memory audit` 直接打印三层实测 token。
- **一键迁移**：Launcher `/memory` → “数据库迁移”和 `picoclaw memory migrate` 均支持 v1 → v2 → v3；DDL 与版本号在同一事务内，重复执行安全。
- **CLI**：新增 `memory repair`、`memory inspect`、`memory rebuild-fts`、`memory forget`、`memory replay-forget`、`memory capsule`。
- **API**：新增 `GET /api/memory/ops`、`GET /api/memory/capsule/{id}`。

## 修复

- 台词或设定稿不再被写进 `real/profile`：`记住` 只在句首生效，引号/【】内容按比例跳过，称呼提取不会把「你叫我什么？」当成改名。
- 未知 predicate 不再直接丢弃原值，保留在 `attributes.original_predicate`；白名单补齐库里已在用的 `助手人设 / 系统架构 / 备份规范 / 场景 / 世界观`。
- `pinned_core` 条目不会被自动 supersede；冲突的新值进入待审核，只能通过 `correct --force` 显式替换。
- `flushUsage` 更新 `use_count` 不再触发 FTS 重建，避免每 5 秒一次写入放大。
- 备份收敛到 `memory/backups/`，迁移和批量修复共用轮转，固定保留最新 2 份。
- 迁移会记录孤儿 sources / 断链 supersedes 的数量（参考库为 9 / 129），不再静默丢弃。

## 升级

1. 停止 gateway 和 launcher。
2. 备份 workspace。
3. 启动 0.5.10，打开 `http://localhost:18800/memory` → “数据库迁移”执行迁移。
4. 命令行等价操作：`picoclaw memory migrate`。迁移幂等，每次都会先做 `VACUUM INTO` 备份。
5. 用 `PRAGMA integrity_check` 和 `picoclaw memory audit` 验证。
